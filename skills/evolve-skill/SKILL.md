# Run the full ecommerce workflow

Move from product intake to research, creative production, and test review.

## Inputs

Product materials and any completed steps.

## Steps

1. Determine whether the product is at intake, evidence review, planning, production, or test review.
2. Collect the inputs required at that stage and complete only the requested work.
3. Return the current checkpoint, evidence IDs, decision, and next practical action.

## Decision checks

Map the requested decision to a lesson, prompt, template or account artifact. Open the accessible item before attributing a method to it. A document title or remote link is a discovery lead. If it cannot be read, name the missing material and use an identified portable method.

Keep the exact original prompt intact in an authorized installation and supply the target context separately. Note which source actually informed the deliverable and which decision it changed. Retrieve only the lessons and inputs needed for the requested scope.

For a decision about desire, readiness, category claim exposure, proof, or the placement of a message, use [Choosing a direct-response message](references/direct-response-decisions.md). Apply the relevant distinction inside the selected Evolve stage. Keep the product’s own evidence with the resulting choice.

If an authorized course pack is available, consult Course Prompt Routing and the course prompt manifest for this decision.

Use [Choosing a method](references/choosing-a-method.md) when plausible approaches imply different actions. Choose a book reference only when it changes the current decision. For the opening, argument or demonstration use [Copy and proof decisions](references/book-copy-decisions.md). For competing explanations of buyer behavior or friction at a choice use [Buyer behavior and evidence](references/book-customer-decisions.md). For the alternative, offer terms or acquisition economics use [Offers, positioning and acquisition](references/book-offer-decisions.md). Keep Evolve’s selected stage, approved promise and original prompt sequence. Treat each book technique as a hypothesis until current product or customer evidence supports using it.

## Deliverable

An ecommerce deliverable and the next checkpoint.

Keep source details with the deliverable. Label assumptions and missing evidence. Preserve the scope and any approvals supplied by the user.

## Decision checks for this skill

Carry the selected idea, proof and version through stage gates. Refresh facts if the SKU or offer changes midstream.
